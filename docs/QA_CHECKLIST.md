# 実機テスト計画（Release/QA チーム）

リリース候補（`vX.Y.Z-rc.N`）を内部テストで配信したあとに行う手動テストです。自動テスト（`flutter test`、Functions の unit・emulator テスト、`check_release.sh`、`check_16kb.sh`）は CI で通っている前提です。

- **優先度**: **S** = スモーク（正式版のタグを付けたあと・修正版のたびに必ず行う。約 30 分）、**A** = 各 rc で行う、**B** = メジャーリリースと関係する変更があったときに行う。
- 結果は §14 の表に記録し、**A 以上で不合格が 1 つでもあれば、そのビルドは製品版にしません**（PM が例外を判断した場合を除く）。
- テストに使う子どもの絵は、保護者の許可を得たもの（またはスタッフが描いたもの）だけにし、写真や結果を外部に出しません。

### 0.2 アカウントと環境
- 内部テストに登録した Google アカウント（大人）。課金テストには Play Console の「ライセンス テスト」に登録したアカウントを使います（実際には請求されません）。
- Firebase は本番プロジェクト。App Check の指標と Functions のログを見られる人が 1 人つきます。
- 広告は内部テストのビルドではテスト広告が出る設定であることを確認します（本番の広告をテストで何度も見ない）。
- 用意する素材（§3・§4）: 紙、クレヨン、色鉛筆、マーカー、鉛筆、罫線のノート、色画用紙、印刷した画像、写真。

## 4. 絵の受け付けと隠し要素（SPEC §3.2・§3.5。結果は社内だけに記録）

次の素材を用意し、**端末だけの判定**と**クラウド判定あり**の両方で、受け付けたか・内部の verdict・skill10 を記録します（開発者向けに `adb` で `characters/<id>.json` を見る。画面には何も出ないのが正しい）。

| 素材 | 数 | 期待 |
|---|---|---|
| K: 4〜10 歳の子どもの絵（保護者の許可を得たもの） | 20 枚以上 | 受け付け、verdict なし、skill10 ≤ 750 |
| AS: 大人が本気で描いた絵 | 10 枚 | 受け付け（隠し要素になってよい） |
| P: 印刷した画像 / S: 画面を撮った写真 | 10 / 5 枚 | **受け付ける**（v2）。verdict が printed / screen |
| R: 実物の写真（人、ペット、部屋） | 5 枚 | 端末でも「かみに かいた えを とってね」で**受け付けない** |
| C: アプリで かいた絵 | 10 枚 | 受け付け、`source: canvas`、verdict なし |

| ID | 優先 | 合格条件 |
|---|---|---|
| 4.1 | A | K の **90% 以上**が verdict なし・skill10 ≤ 750。K が写真として弾かれることは 0 件 |
| 4.2 | A | R はすべて弾かれる。P・S は受け付けて誕生する |
| 4.3 | S | **どの素材でも誕生・名前・ずかん・結果の画面が同じ見た目と言葉**。「しょぼ」「げいじゅつか」「たいき」などの言葉が一切出ない |
| 4.4 | A | 隠し要素のキャラを Lv49 → Lv50 にする（デバッグ用のデータ）| ふつうのキャラの Lv50 と同じ「しんか！ でんせつに なった！」。見た目がでんせつ（金のオーラ）になり、違いが分からない |
| 4.5 | A | クラウド判定ありのとき、K で skill の平均が端末だけのときより 10 以上上がらない |

## 8. 広告・課金・クラッシュレポートの同意（SPEC §10、docs/COMPLIANCE.md）

**v2.0 は課金オフ（`IAP_ENABLED=false`）**: 8.8〜8.17 の課金の項目は、課金を有効にしたビルドだけで行う。課金オフのビルドでは「おうちのひと」にショップと「アプリ内課金」の許可が**無い**こと、Play の購入画面がどこからも開けないことを確認する（S）。**iPhone 版は広告なし**: 広告の許可の項目自体が無く、結果画面に広告のボタンが出ない（S）。

### 8.0 準備
- **広告**: 内部テストのビルドは release.yml で本物の AdMob ID が入るので、QA 端末は AdMob の**テストデバイス**に登録する（AdMob → 設定 → テストデバイス。または logcat の `Use RequestConfiguration.Builder().setTestDeviceIds` に出る ID）。手元のビルドは既定で Google のテスト ID（「Test Ad」と表示される）。本番の広告を自分でタップしない。
- **課金**: Play Console → 設定 → **ライセンス テスト**に QA の Google アカウントを登録（端末の Play ストアもそのアカウント）。購入画面に**テストカード**が出る: 「テストカード、常に承認」「常に拒否」「承認は遅れて行われる（数分後に承認／拒否）」= pending の確認用。実際には請求されない。
- 商品 `slots_24`・`frame_pack_1`・`no_ads_pass` が Play Console で「有効」になっていること（無効だと「価格: —」で買えない）。
- 通信の確認（8.9・8.15）は、プロキシ（mitmproxy など）か `adb shell dumpsys connectivity`／Android Studio の Network Inspector を使う。

| ID | 優先 | 手順 | 合格条件 |
|---|---|---|---|
| 8.1 | S | 保護者が広告を許可していない状態でバトルを終える | 広告のボタンも広告も一切出ない |
| 8.2 | A | 許可したあと「どうがを みて けいけんち 2ばい」 | 見る前に「おうちのひとに きいてから みてね」「こうこくが ながれるよ」が必ず出る。「やめる」なら流れない。子どもが自分で押したときだけ流れ、勝手に流れない（インタースティシャルやバナーは無い） |

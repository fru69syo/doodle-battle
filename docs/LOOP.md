# 描く遊びをくり返す（Loop チーム） — 設計メモ

SPEC §11.2-3 の実装メモ。担当は `app/lib/features/drawing_loop/` と `app/test/features/drawing_loop/`。
目的: 最初の「絵が動いた！」のあとも、**描くこと**を遊びの循環に何度も戻す。**ステータス・バトルの数値・サーバーには一切影響させない**（見た目だけ）。

## 0. まとめ（決定事項）

| 項目 | 決定 |
|---|---|
| おだいのごほうび | **見た目のバッジとスタンプだけ**（XP は渡さない。XP → Lv → ステータスにつながり、「ステータスに影響させない」に反するため） |
| スタンプ | 1 日 1 個、**累計だけ**数える。連続日数は持たない・表示しない。描かなかった日は普通の日（×印も「おしい」も出さない） |
| おだいの判定 | 内容は判定しない（子どもを信じる）。「おだいで かく」を押してから描き終えた絵がスタンプになる |
| パーツ枠 | Lv5 / Lv10 / Lv20 で 1 / 2 / 3 枠（最大 3）。わざの絵は Lv1 から描ける（序盤から循環に入れるため） |
| 取り込み | パーツ・わざの絵も **カメラだけ**。新しいキャラと同じ `drawingAnalyzerProvider` を通すので、Trust チームの拒否理由（AI・デジタル・印刷物など）がそのまま効く。拒否時は解析器の `message` をそのまま出す |
| 元の絵 | **変更しない**。パーツ一覧と各パーツの PNG を別に保存し、表示用の合成画像はキャッシュ（いつでも作り直せる＝可逆） |
| オンライン | スナップショットは今まで通り元の絵（`CharacterRepository.readImage`）だけ。`RegisterCharacterRequest` に cosmetics は入らない（テストあり）。サーバー変更なし |

## 1. きょうの おだい

- `odai/odai_prompts.dart`: 通年 **140 個** ＋季節 4 プール（各 6〜7 個）＋行事 12 種（しょうがつ・せつぶん・ひなまつり・おはなみ・こどもの ひ・つゆ・たなばた・おつきみ・ハロウィン・しちごさん・クリスマス・おおみそか）。ひらがな（外来語だけカタカナ）、分かち書き、漢字なし（テストで検査）。**追記のみ**（id はプール＋位置。バッジには文言も保存するので過去の表示は変わらない）。
- `odai/daily_odai.dart` `odaiFor(DateTime local)`: 端末のローカル日付（Y/M/D）だけで決まる純関数。オフラインで動く。
  1. 行事の期間 → 行事のおだい
  2. 3 日に 1 日 → その季節のプール
  3. それ以外 → 通年プールを「互いに素な歩幅」で巡回（全部出るまで重複なし、連続する日に同じおだいは出ない）
  日数は `DateTime.utc(y,m,d)` 同士の差なので、夏時間・タイムゾーンでずれない。
- ホーム: `OdaiHomeCard`（「きょうの おだい」「おだいで かく」、スタンプ数、カレンダーへ）。もらった日は「きょうの スタンプ もらったよ！」と「また かいてみる」。
- 流れ: 「おだいで かく」→ `activeOdaiProvider` に今日のおだいを記録 → 普段の かく → たんじょう → なまえ。保存時にキャラへ `OdaiBadge`（id・日付・文言）を付け、スタンプを押して「スタンプ ゲット！」。普通の「かく」ボタンは記録を消す。
- ずかんが満杯のとき: 説明を出してずかんへ。**パーツやわざの絵を描いてもスタンプになる**（スタンプの kind = character / part / effect）。
- カレンダー（`/odai`、`StampCardScreen`）: 月ごとの表、今日に枠、スタンプを押すとその日のおだいとキャラ。累計 5 個ごとにスタンプの絵柄が変わる（はなまる → ほし → にじ → おうかん → ロケット）。文言は「すきな ひに かいてね。かいた ひに スタンプが つくよ」。未来の月には進めない。

## 2. パーツを かきたす

- キャラ詳細の「かきたして あそぼう」→ 空き枠 → `PartStudioScreen(addNew)`: 紙に描く → 撮影 → 解析（切り抜きを使う）→「なにを かいたの？」（ぼうし・つばさ・つの・しっぽ・もちもの・かざり）→ 配置 → 「できた！」。
- 配置エディタ（`parts/part_editor.dart`）: 1 本指でドラッグ、2 本指でピンチ（大きさ）とひねり（回転）、タップで選択。子ども向けにボタンでも操作できる（ちいさく・おおきく・まわす・まえに/うしろに・はずす）。種類ごとに初期位置があり、つばさ・しっぽは最初から「うしろ」。
- 変換（`domain/cosmetics.dart` `PartTransform`）: 中心 (cx, cy) は元の絵の幅・高さに対する割合（はみ出し可、±0.6 まで）、scale は「パーツの長辺 ÷ 元の絵の長辺」（0.12〜1.6）、rotation は時計回りのラジアン、behind は元の絵の下に描くか。エディタと合成器は同じ `partToBase()` を使う（見たまま合成される）。
- 合成（`parts/composite.dart` `renderComposite`、純 Dart・Isolate で実行）: 元の絵とパーツの外接矩形に合わせてキャンバスを広げ、長辺 ≤512px。パーツには白いフチ 2px（シール風）。**進化で目立たせる**: かがやき＝属性色のグロー 5px、でんせつ＝金のグロー 7px＋パーツ 1.15 倍。
- 表示: `CharacterPicture` が `characterDisplayImageProvider` を使うので、ずかん・詳細・バトル・オンライン（自分の端末だけ）・カレンダーに合成が出る。AR は `CharacterArScreen` が `DisplayImageService.displayImageFor` を渡すので、**立て札 GLB は合成画像から毎回作り直される**。
- 合成画像は `display_<署名>` としてキャッシュ。署名＝パーツ一覧＋進化段階＋属性の SHA-1。進化したら自動で作り直し、古いキャッシュは消す。
- はずす: 確認のうえパーツの PNG を消す。元の絵は一切触らないので完全に元に戻る。

## 3. わざを かく

- 詳細の「わざの え」→ ぞくせいわざ / ひっさつ → 撮影 → 解析 → プレビュー（キャラから的へ飛んでいく）→「これに する！」。「もとに もどす」で既定のエフェクトへ。
- バトル（`BattleArena` に `effectImages` を追加、既定は空）: ぞくせいわざ・ひっさつの `MoveEvent` で `BattleDisplay.effectCue` を立て、`MoveEffectLayer` が攻撃側のスプライト中心から相手へ 0.7 秒で飛ばす（60% で到着、少し揺れながら拡大 → はじけて 1.9 倍に広がりながら消える。左向きに飛ぶときは左右反転）。絵が無いときは属性アイコン（ひっさつは金の星）。CPU とオンラインの相手は常に既定。オンラインでも自分の絵は自分の端末にだけ出る。

## 4. データとファイル

- `Character.cosmetics`（`CharacterCosmetics`: `parts`・`effects`・`odai`）を**追加**。空なら JSON に書かない（v1.0 のファイルはそのまま）。読み込みは寛容: 壊れたパーツ・未知の種類・未知の項目は捨てる／`accessory` にする／範囲に丸める。cosmetics が壊れていてもキャラは失われない（テストあり）。
- `lib/data/drawing_loop_storage.dart` `DrawingLoopStorage`: `<documents>/drawing_loop/<characterId>/<name>.png`（`part_<id>`、`fx_<move>_<時刻>`、`display_<署名>`）と `drawing_loop/stamps.json`。`main.dart` で `FileDrawingLoopStorage` に差し替え（既定はメモリ）。
- 「おわかれ」でそのキャラの素材を削除、「すべてのデータを削除」でスタンプも含めて全削除。
- ルート追加: `/odai`、`/zukan/:id/parts`、`/zukan/:id/parts/new`、`/zukan/:id/effect/:move`。

## 5. 他チームへ

- **Family（カード印刷）・Video（動画）**: キャラの絵は `ref.read(displayImageServiceProvider).displayImageFor(c)`（PNG、パーツ込み）を使ってください。原画（紙の絵）として元の切り抜きが要るときは従来どおり `CharacterRepository.readImage`。わざの絵は `effectImageFor(c, DrawnMove.element)`。ローカル対戦では `BattleArena(effectImages: {Side.a: watchMoveEffects(ref, a), Side.b: watchMoveEffects(ref, b)})` で両者の絵が飛びます。
- **Trust**: パーツ・わざの絵も `drawingAnalyzerProvider.analyze()` を通し、`rejectReason.message` を表示しています（enum に `switch` していないので理由の追加で壊れません）。表示文に skill / しょぼは出していません。
- テスト: `pumpApp(overrides: [...])` を追加。Isolate はテストの fake async で動かないので、ハーネスで `compositeRunnerProvider` を同期版にしています。

## 6. 未決定・確認したいこと

1. ごほうびに XP を足すか（今は見た目だけ）。足すなら「次の 1 戦の XP +20%」程度で、サーバーの Lv 上限検証の範囲内。
2. 小さいパーツ（つのだけ等）が `nearlyEmpty` で弾かれないか実機で確認したい（しきい値は低いので大丈夫な見込み）。弾かれる場合は解析器に「パーツ用」モードを Vision/Trust と相談。
3. おだいの追加・季節更新（例: 2 週間ごとの追加）は運用で。文言は追記のみ。
4. 合成のグロー・白フチの見え方、ひねり操作のしやすさは 5〜7 歳のプレイテストで確認したい。

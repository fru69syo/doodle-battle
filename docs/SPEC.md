# おえかきファイターズ (doodle-battle) 製品仕様 v2.0

子どもが描いた絵をキャラクターにして、リアルタイムのゲージ制バトルで戦わせ、育てるゲーム。
**子どもらしく元気に描いた絵ほど強くなる。** AI で作った絵やプロのような絵は、とても簡素で弱いキャラになる（理由は画面では一切説明しない。§3.5）。

- この文書が**現在の仕様の正**。v1.0〜v1.1 の仕様と、v2.0 を決めたときの原文は [`docs/archive/SPEC_v1.md`](archive/SPEC_v1.md) にある。2026-10-12 より前に書かれたコードや文書の「SPEC §番号」は、旧版の番号を指す（対応表は §16）
- 数値の正（normative）は `shared/battle_spec_v3/battle_spec_v3.json`、正解例は `golden_vectors.json`。式の詳しい説明は [`docs/GAME_DESIGN_V2.md`](GAME_DESIGN_V2.md)、製品のエンジンは [`docs/BATTLE_V3.md`](BATTLE_V3.md)
- 対象: 6〜12 歳の子ども。Google Play の「ファミリー」ポリシーに従う。配信は日本のみ、日本語のみ（ひらがなを主にする）
- プラットフォーム: Android を先に出す（minSdk 24 = Android 7 から / targetSdk 36）。そのあと iOS
- 技術: Flutter 3.47 / Dart 3、Riverpod、go_router。Firebase と GCP（Cloud Run・Terraform）。AI は Anthropic の Claude
- この文書には内部だけの仕組み（§3.5 の隠し要素など）も書いてある。**内部用の名前や数値は、画面・文言・ストア説明・API の応答・ログの表示に出さない**

---

## 1. 用語

| 用語 | 意味 |
|---|---|
| 子どもの絵らしさ（`kid`） | 0–100。絵の元気さ（インクの量・色の数・大きさ・線の勢い）と、上手すぎなさ（線のなめらかさ・対称性・陰影・描き込みの少なさ）を合わせた値。高いほど能力の合計が大きい。**画面には出さない** |
| 能力 | HP・SP・STR・VIT・DEF・INT・RES・DEX・AGI・LUK の 10 種類（§4.1） |
| 属性 | **グー（かたい）／チョキ（するどい）／パー（ひろがる）**。キャラの形で決まる。技にも属性がある（むぞくせいもある） |
| 技の枠 | 1 体が持つ技は最大 4 つ。Lv1 で 2 つ、Lv10 で 3 つ目、Lv50 で 4 つ目（ひっさつ）（§5） |
| ゲージ（ATB） | AGI に応じて時間でたまる。満タンになると技を出せる（§6） |
| さきどり | ゲージがたまっている間に、次に出す技を先に選んでおくこと。満タンになった瞬間に出る |
| おまかせ | AI が代わりに技を選ぶこと。時間切れのとき・おまかせをオンにしたとき・CPU・ゴーストで同じ AI を使う |
| ゴースト | オンラインで相手が見つからないとき、他の人が登録したキャラを AI が動かして相手にする |
| 隠し要素（内部名 `bloomer`） | AI で作った絵やプロのような絵のキャラ。Lv49 まではとても弱く、Lv50 で強いキャラに作り直される（§3.5）。**内部用。画面には出さない** |
| コストモード | サーバーの月の予算に応じて、費用のかかる機能を自動で止める仕組み。normal / saving / minimal（§11.3） |

## 2. 体験の流れ

1. **初めて起動したとき**: 保護者セットアップ（保護者ゲート → 同意 → 各機能の許可）
2. **「かく」**: 次のどちらかで絵を作る
   - 紙に描いた絵をカメラで撮る（基本。撮影ガイドを出す）
   - **アプリ内のお絵かきツール**で描く（「アプリで かく」）。クレヨン・ペン・ふで・けしごむ、12 色、もどす／やりなおす。**画像の取り込み・貼り付けはできない**
3. **「たんじょう」**: 解析の演出 → キャラ誕生（属性・技を見せる。能力は星やアイコンで見せ、内部の値は出さない）→ 名前を付ける（NG ワードはその場で弾く）
4. **「うごく ところを なおそう」**（やらなくてもよい。「あとで」で飛ばせる）: 自動で入った関節を子どもが手直しする（§8.2）
5. **「ずかん」**: 持っているキャラの一覧。キャラのページから関節の手直し・カード印刷・動画・AR
6. **「ぼうけん」（一人用）**: 10 ワールド × 10 ステージ。ストーリーなし（§7.1）
7. **「オンライン」**: キャラが **Lv5 以上**で、保護者が許可していれば遊べるレート戦（§7.2）
8. **「かぞく たいせん」**: 1 台の端末で、親子・きょうだいが交互に操作する（§7.3）
9. **「おうちのひと」**: 保護者ゲートの先の設定。各機能の許可、データの削除

## 3. キャラの作り方

### 3.1 解析（端末内で行う。isolate で実行）
- 紙の絵: 正規化 → 紙の検出と台形補正 → 前景の切り抜き → 特徴量（`DrawingFeatures`）→ 元気さ（energy）と上手さ（skill）。詳細は `docs/VISION.md`
- お絵かきツールの絵: 同じ処理をするが、**紙の検出と、印刷・画面・写真・デジタルの判定は省く**（キャンバスそのものが紙で、絵は子どもの指からしか来ないため）。描いた線の記録は関節の推定にも使う（§8.1）
- **同じ画像からは必ず同じキャラができる**。ランダム要素は、切り抜き画像の SHA-256（画像ハッシュ）を seed にして決める

### 3.2 受け付けるもの・受け付けないもの
| 入力 | 扱い |
|---|---|
| 子どもが手で描いた絵（紙・アプリ） | 受け付ける |
| AI で作った画像、デジタルイラスト、印刷物、画面を撮ったもの、プロのような上手な絵 | **受け付ける。ただし隠し要素のキャラにする**（§3.5）。子どもには何も伝えない |
| 写真（特に実在の人物）、不適切な画像（暴力・性的・差別・著作権キャラの丸写しなど）、個人情報（名前・住所などの文字）が写っているもの | **受け付けない**。表示は「かみに かいた えを とってね」など、責めない言い方にする |
| ほとんど何も描いていない絵 | 描き直してもらう |

- 本物の子どもの絵を誤って弱くしたり拒否したりしないことを最優先にする（迷ったら子どもの絵として扱う）

### 3.3 クラウドの判定（保護者が許可した場合だけ）
- 切り抜いた絵（512px）を Cloud Function `judgeDrawing` に送り、Claude が「何の絵か」「名前の候補 3 つ」「上手さ」「絵の出どころ（手描き／AI・デジタル／写真・印刷・画面）」「適切か」と、**技 4 つの提案**を返す（§5.4）
- 上手さは端末とクラウドの値を混ぜる。クラウドが失敗・時間切れ・コストモードで止まっているときは端末の判定だけで続ける
- 画像はサーバーに保存しない（処理が終わったら捨てる）。**絵を AI の学習に使わない**

### 3.4 能力の決め方
```
kid    = (6·energy + 4·(100 − skill)) / 10              // 0–100
予算   = (1400 + 3·kid) · jitter / 400                   // Lv1 の 10 能力の合計。jitter は 97–103 %（画像ハッシュで決まる）
```
- 例: kid 80 → 約 410、kid 95 → 約 421、kid 60 → 約 395
- 予算を 10 能力に分ける。各能力の「なりやすさ」は**見た目の特徴**から決める（各能力は予算の 5 % 以上、さらに画像ハッシュで ±15 % の個性）
  - 大きくて丸い → HP、とがって赤くて太い → STR、硬そう・太い線・角ばっている → DEF・VIT・RES、細長くて小さい → AGI、細い線で手足が多い → DEX、カラフルで複雑 → INT・SP、ゆがみと運 → LUK
- **属性**も形で決まる: どっしり・丸い・太い → グー、とがって細長い → チョキ、色が多くて大きい → パー
- 式の詳細と例は `docs/GAME_DESIGN_V2.md` §2〜§3

### 3.5 隠し要素（内部用。画面・文言・API に一切出さない）
- **判定**: 上手さ（skill）が 75 を超える、または絵の出どころが AI・デジタル・印刷・画面と判定されたもの
- **Lv1〜49**: 能力の予算は 50 %、技の予算は 70 %。見た目もシンプル（色を減らし、動きを控えめに）。同じレベルの子どもの絵にはほぼ勝てない（Lv49 でも普通のキャラの Lv12 くらい）
  - そのかわり経験値は 2 倍（一人用）／1.5 倍（オンライン）。弱くても Lv50 まで届くようにするため
- **Lv50 で作り直す**: 能力は「kid 75（子どもの絵の平均くらい）の Lv50」と同じ強さにし、技も 4 つとも作り直す。Lv50 からの成長は普通のキャラの 1.12 倍。Lv100 では普通のキャラに約 63 % 勝つ（大器晩成）
- **ばれないようにする**: Lv50 では**全員**が「でんせつ」に大進化する（金のオーラ、技が +5 %）。隠し要素のキャラだけが作り直されていることは、見た目からも数字からも分からない
- 家族対戦のハンデで Lv50 を超えても、作り直し前の形のまま。サーバーは隠し要素の情報（`engine.trust`）を持ち主の端末にも送らない

## 4. 能力・レベル・成長

### 4.1 10 種類の能力
| 能力 | バトルでの効き方 |
|---|---|
| HP | 最大 HP（`3·HP + 2·VIT + 能力の平均の 5 倍`） |
| SP | SP の回復の速さ（SP の上限は全員 100、開始時 40） |
| STR | 物理技の攻撃力 |
| VIT | 最大 HP の一部、状態異常にかかりにくい |
| DEF | 物理技への防御 |
| INT | 特殊技の攻撃力、回復量 |
| RES | 特殊技への防御 |
| DEX | 命中、一部の技の攻撃力 |
| AGI | **ゲージがたまる速さ**（相手との比）、回避、一部の技の攻撃力 |
| LUK | 会心、状態異常を当てる確率、回避 |

- **ATK という固定の能力は無い**。技ごとに決まった式で計算する（例: `STR80_AGI20` = STR×0.8 + AGI×0.2）。防御側は物理なら DEF、特殊なら RES を使う

### 4.2 レベルと経験値
- 最大 **Lv100**。1 レベルにつき Lv1 の値の平均 4 % 伸びる（能力ごとに 3.2〜4.8 %。なりやすい能力ほど伸びやすい）
- 次のレベルまでの経験値: `60 + 20·L + 3·L²/4`
- 一人用: 勝ち 100 / 負け 40 × ステージの倍率。初クリアは 2 倍。**自分より 10 以上低いステージを繰り返すと減る**（経験値稼ぎの対策）
- リワード広告で経験値 2 倍（一人用だけ、1 日 3 回まで、Android だけ、保護者の許可制。§10.2）
- オンライン: 勝ち 150 / 負け 60 × レベルの倍率。1 日 20 戦まで、同じ相手とは 60 分に 1 回まで、途中で切断した負けは 0
- 目安（1 日 10 戦）: Lv10 は 2 日目、Lv50 は 1 か月前後、Lv100 は 4 か月前後
- **パワーのたね（自分で能力を振る仕組み）は無い**。能力は絵の見た目で決まる

### 4.3 進化（見た目だけ。能力のボーナスは Lv50 の技 +5 % だけ）
| Lv | 名前 | 変わること |
|---|---|---|
| 10 | かがやき | オーラ。3 つ目の技 |
| 25 | きらきら | 動くと光の粒が出る |
| 50 | でんせつ | **大進化**（金色のオーラ）。4 つ目の技（ひっさつ）、全部の技 +5 % |
| 75 | にじ | オーラが虹色になる |
| 100 | おうかん | 王冠、カードに金の枠 |

## 5. 技

### 5.1 技の枠
| 枠 | 増えるとき | 予算 | きまり |
|---|---|---|---|
| 1「いつもの わざ」 | Lv1 | 100 | ダメージ技・**自分の属性**・SP 0・クールダウン 0・溜めは 0.5 秒以下（いつでも使える） |
| 2 | Lv1 | 100 | 属性は**自分と違うもの**（補助技はむぞくせい）。不利な相手への逃げ道 |
| 3 | Lv10 | 120 | 自由 |
| 4「ひっさつ」 | Lv50 | 150 | ダメージ技・**むぞくせい** |

- 予算には技の倍率を掛ける: `95 + kid/10`（95〜105 %）。Lv50 で +5 %。隠し要素は Lv49 まで 70 %

### 5.2 技の種類（テンプレート 10 種）
| 種類 | 効果 |
|---|---|
| strike / combo | 物理のダメージ（1 回／2〜3 回） |
| blast / barrage | 特殊のダメージ（1 回／2〜3 回） |
| heal | 回復。**使うたびに 100 → 75 → 50 → 25 % と弱くなる** |
| power_up | 自分の能力を上げる（一定時間） |
| weaken | 相手の能力を下げる（一定時間） |
| poison | 「ねばねば」: 毎秒、最大 HP の 1.5 % を 8 秒 |
| paralyze | 「ビリビリ」: 相手のゲージのたまり方が 60 % になる（6 秒） |
| barrier | まもり: 受けるダメージを 20〜60 % 減らす（一定時間） |

- ダメージ技には追加効果を 1 つ付けられる（ねばねば／ビリビリ／弱体／吸収）
- **眠り・行動不能・即死は入れない**（子どもが何もできない時間を作らない）
- 技には威力・命中・会心・SP・溜め時間・クールダウンがある。すべての数値は**予算ポイント**の中に収める（`docs/GAME_DESIGN_V2.md` §5.3）

### 5.3 3 すくみ
- グー > チョキ > パー > グー。技の属性が相手キャラの属性に**有利なら ×1.5、不利なら ×0.75**、それ以外は ×1（むぞくせいの技はいつも ×1）。倍率は**ダメージに**掛ける
- 有利な相手への勝率は 65〜70 %

### 5.4 技の作り方（AI は数値を決めない）
- **クラウド（保護者の同意あり）**: Claude が技 4 つの「種類・属性・名前・説明・演出・数値の案」を JSON で出す。ゲームの検証器（`validateAiMove`）が、枠のきまりと予算に合うよう**数値を縮める・不正な技を捨てる**。名前は NG ワード・文字の種類（ひらがな・カタカナ 1〜10 文字）を検査し、サーバーの審査も通す
- **端末（同意なし・失敗・コストモード）**: 画像ハッシュから決まるテンプレートで作る。名前は「属性ごとの擬音 + 種類ごとの名詞」（例: ごつごつパンチ）
- **Lv10・Lv50 で増える技**: `generateMove` で Claude に名前と説明だけを頼む（失敗したらテンプレートの名前）。隠し要素の作り直し後の技も同じ
- 技の数値は保存せず、毎回そのレベルの予算で検証し直す。AI の提案や名前への**通報ボタン**がある

## 6. バトル（リアルタイムのゲージ制）

### 6.1 ルール
- 1 対 1。**ターン制ではない**。時間は 10 Hz（0.1 秒ごと）で進み、状態はすべて整数で計算する
- **ゲージ**: 0〜10000。AGI の**相手との比**でたまる（同じ AGI なら 3.6 秒で満タン。AGI が 2 倍で約 1.2 倍の速さ）
- 自分のゲージが満タンになったら、技を選ぶまで**自分のゲージは止まる**。**相手のゲージは止まらないし、遅くもならない**。迷うと自分が損をするだけなので、引き延ばしは有利にならない
- 技を選ぶ制限時間は **5 秒**。時間切れなら**おまかせ**で行動する
- **さきどり**: ゲージがたまっている間に次の技をタップしておける。満タンになった瞬間に出る（待ち時間 0）。後からタップし直すと上書きされる。使えない技（クールダウン中・SP 不足）なら捨てる
  - 理由: さきどり無しだと、選ぶのに 3 秒かかる子は 1 秒で選ぶ子に 20 % しか勝てず、手の速さで勝負が決まってしまうため
- **おまかせ**は満タンになってから 1 秒考えてから選ぶ（おまかせが一番強い操作にならないように）。一人用ではおまかせを常にオンにもできる（小さい子向け）
- 子どもが操作するのは**技を選ぶことだけ**。キャラの移動や演出は自動
- 溜めのある技は、溜めている間ゲージが止まる。技を出したらゲージは 0 に戻り、その技のクールダウンが始まる
- 命中・会心・ダメージの乱数幅は seed 付きの乱数（Mulberry32）で決める。同じ seed と入力なら必ず同じ結果になる
- **60 秒を過ぎるとヒートアップ**（ダメージが毎秒 +3 %、回復は弱くなる）。**3 分で HP の割合で決着**。引き分けは無い
- 戦闘の長さの目安: 違う絵同士で平均 45〜55 秒

### 6.2 おまかせ・CPU の強さ
- 使える技を「相手の HP に換算した点数」で比べて選ぶ（倒せる技は最優先、HP が減ったら回復、相手が溜めていたらまもり など）
- 3 段階: よわい（40 % の確率でランダム）／ふつう（10 %）／つよい（ランダムなし、考える時間 0.4 秒）。おまかせ・ゴースト・サーバーの時間切れは**ふつう**。つよいは CPU だけ

### 6.3 エンジン
- エンジンは純粋なロジックで、Dart（`app/lib/domain/battle_v3/`）と TypeScript（`shared/battle_engine_v3_ts/`）の 2 つ。**128 件の正解例でビット単位まで一致する**ことを CI で確かめる
- 画面（2.5D のステージ、§8.3）は、エンジンが出すイベント（技を出した・当たった・外れた・状態異常・倒れた など）を受けて演出する

## 7. 遊びのモード

### 7.1 一人用（ストーリーなし）
- **10 ワールド × 10 ステージ = 100**。ワールド: らくがき のはら／クレヨン もり／えのぐ うみ／いろえんぴつ やま／ペンギン こおり／マーカー まち／ねんど さばく／はさみ おしろ／にじいろ そら／まっしろ ノート
- ステージ n のおすすめ Lv = CPU の Lv = n。各ワールドの 10 番目はボス
- CPU の強さ: ステージ 1〜20 よわい、21〜60 ふつう、61〜100 つよい。CPU は同梱の子どもの絵 37 体から作る
- 勝率の目安（おすすめ Lv、おまかせ）: ワールドの 1 番目 約 85 % → ボス 約 56〜59 %
- ごほうび: 経験値と、星 1〜3（勝つ／HP 50 % 以上残す／60 秒以内）。星で**見た目のアイテム**（カードの枠・エフェクトの色・スタンプ）がもらえる。能力には影響しない
- 負けたら「おすすめ Lv」と「もうすこし そだてて みよう」を出す（責めない）

### 7.2 オンラインのレート戦
- **Lv5 から**、保護者の許可があるときだけ。登録時のサーバー審査（§9.2）を通ったキャラだけが出られる
- **全員 Lv50 にそろえて戦う**。能力はそのキャラ自身の伸び方で Lv50 に計算し直す。技は**実際に解放している分だけ**（Lv1〜9 は 2 つ、10〜49 は 3 つ、50 以上は 4 つ）。レベルの差でレートが決まらないようにするため
- レートは Elo（開始 1000、下限 600。初めの 20 戦は K=48、その後 24、ゴースト戦は半分）。**数字は見せず、ランクのバッジで見せる**: たまご → ひよこ → うさぎ → きつね → くま → ライオン → ドラゴン → でんせつ。**バッジは下がらない**（一番よかったものを見せる）
- マッチング: レートの差 ±100 から始めて最大 ±400 まで広げる。**20 秒**で相手がいなければゴースト（コストモードで短くなる）
- サーバーが戦闘を進め、サーバーの結果を正とする。端末は技の指示を送るだけ。通信が遅い子のために 0.3 秒の猶予を付ける
- 切断: 10 秒戻らなければおまかせで続ける、30 秒戻らなければ負け（経験値 0）
- **チャットは無い**。表示名は用意した言葉の組み合わせ（例「あおい ドラゴン」）だけ

### 7.3 かぞく たいせん（ローカル）
- 1 台の端末で交互に操作する（相手が選ぶ間は画面を隠す）。サーバーは使わない
- ハンデ（レベルを足す）を選べる。**経験値は入らない**

### 7.4 引き継いだ遊び（v1.1 から）
- **Before/After 動画**: 紙の絵 → 誕生 → バトルの見せ場を 10〜15 秒の縦型動画にする（2.5D で動かす）。子どもの顔と声は入れない。共有は保護者ゲートの先
- **キャラカードの印刷**: 原画とキャラを並べた PDF。数値は出さず、星やアイコンで見せる
- **描く遊びのくり返し**: 毎日の「おだい」、パーツを描き足して見た目を変える（描いたパーツは関節の骨にもなる）、技のエフェクトを描く。**能力には影響しない**
- **AR**: カメラ越しに床や机にキャラを置いて写真を撮る（`docs/AR.md`）

## 8. 2.5D の表現（`docs/PUPPET.md`）

### 8.1 動かし方
- 3D モデルは作らない。**子どもの絵を頭・体・手足などに分け、紙人形のように関節を動かす（2.5D）**
- 端末で自動的に骨組みを入れ（自動リグ）、絵をメッシュにして `Canvas.drawVertices` で描く。古い Android（7〜9）と iOS で同じコード
- お絵かきツールの絵は、描いた線の記録から手足を見つける（体にくっついた腕も分かる）
- 奥行きは、遠近感のある地面・影・背景の重なり（パララックス）・カメラの寄りと引きで出す
- 重い端末では自動で軽い表示に切り替える

### 8.2 関節の手直し（子どもが使う）
- 誕生のあとに「うごく ところを なおそう」を出す（「あとで」で飛ばせる）。キャラのページからも開ける
- 字が読めなくても使えるよう、アイコンと短いひらがなにする。大きな丸いハンドル、常に動くプレビュー、もどす（40 回）・さいしょから・手／足／しっぽを足す・けす
- 手直しした骨組みはキャラに保存し（2 KB 以下）、オンラインの相手にも同じ骨組みで見える

### 8.3 バトルのステージ
- ステージの見た目は 8 種類（10 ワールドに割り当てる）。キャラは自動で動き、カメラがパン・ズーム・ゆれで見せる
- 画面の部品: HP と状態のパネル、ゲージ、技のボタン、5 秒の残り時間の輪、おまかせの切り替え、状態のアイコン、ダメージの数字、「ばつぐん！」「いまひとつ…」

## 9. オンラインとサーバー

### 9.1 認証と安全
- Firebase の匿名認証と App Check。匿名サインインは、保護者がクラウド判定かオンラインを許可するまで行わない
- **自由に入力した文字を他の人に見せることは一切しない**

### 9.2 キャラの登録（`registerCharacter`、`schema: 2`）
- 端末は画像・名前・量子化した特徴量・レベル・経験値・技の提案・骨組み・絵の入手方法（カメラ／アプリ）を送る
- サーバーが行うこと:
  1. **画像の審査（Claude）は必ず行う**。どの入手方法でも、写真・不適切な画像・個人情報は拒否する
  2. 名前と技の名前の NG ワード検査と AI の審査。だめな技の名前はテンプレートの名前にする
  3. **画像ハッシュはサーバーが計算し直す**（アップロードされた PNG の SHA-256）。能力はサーバーが計算し直す（端末の値は信じない）
  4. 「アプリで描いた」という申告は、線の記録と画像が合っているときだけ認める。合わなければ写真と同じに扱う（拒否はしない）。詳細は `docs/TRUST.md` §8
  5. 合格したら変わらないスナップショットとして保存する。隠し要素の情報（`engine.trust`）はサーバー専用で、持ち主の端末にも読ませない
- 古い形式（v1）のスナップショットはオンラインで使えない。v1 から移したキャラは、オンラインに出るときにもう一度登録する（子どもには見せない）

### 9.3 リアルタイム対戦サーバー
- Cloud Run の WebSocket サーバー（`server/realtime/`）。TS エンジン v3 で 10 Hz で戦闘を進める。マッチング、ゴースト、Elo を担当する（`docs/REALTIME_PROTOCOL.md`）
- 隠し要素の情報は、どのメッセージにも入れない（テストで確かめる）

### 9.4 通報
- 対戦相手のキャラ・AI が作った名前や技に通報ボタンを付ける（理由は選ぶだけ）。3 件で非公開にし、運営が確認する

## 10. 保護者・安全・収益化

### 10.1 保護者
- 保護者ゲート: 3 秒の長押し + 2 けた × 1 けたのかけ算
- 保護者の設定: クラウド判定 / オンライン対戦 / 広告の視聴 の許可、データの削除（サーバー側も含む）
- 「絵は AI の学習に使いません」を同意画面・ストア説明・プライバシーポリシーに書く

### 10.2 収益化
- **無料で公開する。課金アイテムは出さない**（コードは feature flag で残し、初期値はオフ。オーナーの副業申請が通ったら有効にする。商品は保存枠・フレームパック・こうこくなしパス 320 円の予定）
- **リワード広告は Android だけ**（「どうがを みて けいけんち 2ばい」、1 日 3 回、保護者が許可したときだけ）。見る前に「おうちのひとに きいてから みてね」を出す
- 広告の設定: 児童向けとして扱う（TFCD）、レーティング G、パーソナライズしない、広告 ID を使わない（AD_ID 権限を外す）。保護者が許可するまで SDK を初期化しない
- **iPhone 版は広告なし**（Apple の Kids カテゴリーの審査の危険を避けるため）
- ガチャは入れない。Firebase Analytics は使わない（Crashlytics は保護者が許可したときだけ）

## 11. AI・クラウド・予算

### 11.1 AI の提供元は Claude（2026-10-11 決定）
- 絵の判定・登録時の審査・技の名前づくりに Anthropic の Claude を使う。鍵は Secret Manager の `ANTHROPIC_API_KEY`、モデル名は Functions のパラメーター `CLAUDE_MODEL`（**リポジトリにモデル名を書かない**）
- Gemini・Vertex AI・Firebase AI Logic は使わない。どれも利用規約で、18 歳未満を対象にしたサービスや 18 歳未満が使う可能性が高いサービスでの利用を禁止しているため
- 子ども向けのサービスで使うための対策:
  1. Claude に送る**すべてのシステムプロンプトに子どもの安全のルール（`CHILD_SAFETY_RULES`）を入れる**。テストで確かめる
  2. プライバシーポリシーで、AI を使っていることと、子どものプライバシーに関する法令（COPPA など）に従うことを公表する（`site/privacy.html`）
  3. Claude の出力はそのまま子どもに見せない。サーバーで検査してから使う
  4. Anthropic Console で月の利用上限を設定する（目安 2,000 円）

### 11.2 クラウドは GCP
- Firebase（認証・Firestore・Storage・Cloud Functions）に加えて、Cloud Run（リアルタイム対戦）、Terraform（構成をコードで管理）、Workload Identity 連携（GitHub Actions から鍵なしでデプロイ）、Budget と Pub/Sub（予算の自動停止）、Cloud Monitoring を使う。オーナーの学習も兼ねる（`docs/LEARN_GCP.md`）

### 11.3 予算と自動調整
- **サーバーの予算は月 5,000 円まで**（Anthropic の利用料を含む）
- 予算に近づくと、コストモードを自動で切り替える（`shared/cost_mode/cost_mode.json`）。**子どもからは切り替わったことが分からないようにする**

| モード | いつ | 変わること |
|---|---|---|
| normal | ふだん | すべて使う。ゴーストまで 20 秒 |
| saving | 予算の 80 % | クラウドの判定・技の名前づくりを止めて端末だけにする。ゴーストまで 8 秒 |
| minimal | 予算の 100 % | さらに対人戦を止め、ゴーストだけにする（3 秒） |

- 登録時の審査は安全のため**止めない**（失敗したら登録させない）

## 12. 対応端末と性能
- Android 7〜9（minSdk 24）にも対応する。iOS も同じ画面を使う
- 2 体のキャラ + ステージの描画は 1 フレーム 1 ms 未満（デスクトップでの計測）。実機（古い GPU・Impeller）での確認は未了
- 解析は中位機種で 3 秒以内

## 14. 品質の基準
- `dart format` の差分なし、`flutter analyze` 警告ゼロ、`flutter test` がすべて通る
- Dart と TS のエンジンが正解例でビット単位まで一致する
- Functions は lint・ビルド・ユニット・emulator のテスト、リアルタイムサーバーは lint・テスト・コンテナのビルドを通す
- リリース AAB は `scripts/check_release.sh`（権限・広告 ID）と `scripts/check_16kb.sh`（16 KB ページ）を通す
- 隠し要素が画面に出ないことをテストで確かめる（`hidden_state_guard_test.dart`）

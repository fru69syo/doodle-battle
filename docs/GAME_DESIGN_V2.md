## 1. 前提

- 入力: 紙の絵（カメラ）またはアプリ内のお絵かき（SPEC §12.2）。Vision の `DrawingFeatures`（docs/VISION.md §3）、energy / skill（同 §4）、Trust の判定（docs/TRUST.md）をそのまま使う
- v2.0 から、**AI 生成・デジタル・印刷物・画面を撮ったもの**は拒否せず、隠し要素のキャラにする（§4.4 の `origin`）。**写真は今までどおり拒否する**: 端末の中では実在の人物の写真かどうかを見分けられないため（SPEC §12.2 の例外を優先した。→ 未決定事項 Q3）
- アプリ内のお絵かきツールで描いた絵は、Trust の「デジタルらしさ」に当たってしまう（ベタ塗りでノイズが無い）。そのため**ツールで描いたものはデジタル判定をしない**（画像は貼れず、描いた経路が分かっているため）。energy / skill は同じ特徴量から計算する（Q4: ブラシの質感でクレヨン向けの値の範囲がずれるので、実機で調整が要る）

## 2. 子どもの絵らしさと予算

```
e10 = round(energy × 10)    s10 = round(skill × 10)        // 0..1000 の整数（クラウド判定のブレンド後）
kid = (6·e10 + 4·(1000 − s10) + 50) / 100                   // 0..100
seed = 画像ハッシュの先頭 8 桁（16 進）→ uint32
rj = Mulberry32(deriveSeed(seed, 10))
jitterPct = 97 + rj.next() % 7                              // 97..103（小さなランダム要素）
budget = (1400 + 3·kid) · jitterPct / 400                   // 例: kid 80 → 410、kid 60 → 395、kid 95 → 421
bloomer なら budget = budget · 50 / 100（§4.4）
```

例（`VISION.md §6` の値）: クレヨンの落書き（energy 91.4 / skill 8.3）→ kid **92**。マーカーの棒人間（39.8 / 20.3）→ kid **56**。

- 「点 1 つ」は今までどおり Vision の `nearlyEmpty` で描き直してもらう。energy の gate があるので、少ししか描いていない絵は kid が下がる
- kid の差の効き目は「シミュレーションで kid 95 と kid 60 が戦うと 75 % 対 25 %」。上手に元気よく描くほど強いが、どの子どもの絵にも勝ち目は残る（§10）

## 3. 10 種類の能力

### 3.1 役割

| 能力 | 戦闘での効き方 |
|---|---|
| HP | 最大 HP = `3·HP + 2·VIT + 5·(10 能力の合計 / 10)`（HP 1 つに偏りすぎないよう、平均値も足す） |
| SP | SP の回復速度（相手との比、§6.4）。SP の上限は全員 100 |
| STR | 物理技の ATK（`STR80_AGI20` などの式。§5.2） |
| VIT | 最大 HP の一部、状態異常にかかりにくい、かかっても短い |
| DEF | 物理技を受けるときの防御 |
| INT | 特殊技の ATK、回復量 |
| RES | 特殊技を受けるときの防御 |
| DEX | 命中、一部の ATK の式 |
| AGI | **ゲージがたまる速さ**（相手との比）、回避、一部の ATK の式 |
| LUK | 会心（相手の LUK との比）、状態異常を当てる確率、回避 |

### 3.2 見た目 → 能力の「なりやすさ」

特徴量は**整数に量子化**してから使う（`FeatureVector.quantize`。浮動小数点を使うのはここだけ。量子化した値を保存し、サーバーに送る）。
`ramp(v, lo, hi)` は 0..1000 の整数。表の重みは 100 分率。

| 能力 | なりやすさ = Σ 重み × ramp | 意味 |
|---|---|---|
| HP | 40 まるさ + 35 大きさ + 25 インク量 | 大きくて丸い → HP |
| SP | 40 色相の数 + 30 インク量 + 30 パーツの数 | にぎやか → SP |
| STR | 40 とげとげ + 30 赤の割合 + 30 線の太さ | とがって赤くて太い → 力 |
| VIT | 40 暗さ + 30 塊っぽさ + 30 大きさ | 重そう → タフ |
| DEF | 45 線の太さ + 35 塊っぽさ + 20 (1 − 細長さ) | 硬そう・角ばっている → DEF |
| INT | 50 色の数 + 30 描き込み + 20 (1 − 対称性) | カラフルで複雑 → INT |
| RES | 40 暗さ + 35 線の太さ + 25 色の数 | 硬そう → RES |
| DEX | 40 (1 − 線の太さ) + 30 パーツの数 + 30 描き込み | 細い線で手足が多い → DEX |
| AGI | 45 細長さ + 35 (1 − 線の太さ) + 20 (1 − 大きさ) | 細長くて小さい → AGI |
| LUK | 50 運（画像ハッシュから）+ 25 色相の数 + 25 (1 − 対称性) | ゆがみと運 |

ramp の範囲（量子化後の単位、spec JSON の `ramps`）: まるさ roundness 200–800‰、大きさ silhouetteCoverage 30–350‰、インク 0–300‰、塊 solidity 500–950‰、とげ spikiness 0–300‰、赤 0–1000‰、線の太さ 1.0–12.0 px、暗さ 200–800‰、色の数 colorUnits（`2·colorCount + achromaticCount`）1–10、色相 balancedHueCount 1–4、描き込み 0–600‰、パーツ convexityDefects 0–8、細長さ elongation 1.00–3.00、対称性 400–900‰。

配分:
```
a_i = Σ(重み × ramp) / 100                          // 0..1000
a_i = a_i × (85 + rj.next() % 31) / 100; a_i = max(a_i, 50)   // ±15 % の個性（画像ハッシュで決まる）
share_i = 50·Σa + 500·a_i                           // 各能力は予算の 5 % 以上
base_i = 最大剰余法(budget, share)                   // 合計がちょうど budget になる。同点なら先の能力
```
引く乱数の順序（移植で一致させる部分）: jitterPct → 運 → 10 能力ぶんの個性（HP から LUK の順）。

例（`tool/_dbg` で作った合成の特徴量）:

| 絵 | kid | 属性 | 予算 | HP SP STR VIT DEF INT RES DEX AGI LUK | 最大 HP |
|---|---|---|---|---|---|
| まんまる（丸い塊・クレヨン） | 91 | グー | 418 | **57** 38 34 53 **63** 39 44 28 27 35 | 486 |
| とげとげ（赤・とがっている） | 85 | チョキ | 401 | 32 47 **49** 37 43 35 41 44 38 35 | 370 |
| ほそながヘビ（細い線・細長い） | 68 | チョキ | 401 | 24 30 37 28 24 40 28 **55** **79** 56 | 328 |
| かたいロボ（太い線・暗い・四角い） | 88 | グー | 428 | 51 39 38 **67** **65** 31 **59** 28 25 25 | 501 |
| にじいろ（色が多い・パーツが多い） | 90 | パー | 430 | 40 **53** 36 37 41 **57** 37 51 37 41 | 409 |
| AI のイラスト（隠し要素） | 51 | パー | 198 | 24 22 14 23 22 22 19 21 17 14 | 217 |

### 3.3 キャラの属性（グー / チョキ / パー）

`score(gu) = ramp(塊) + ramp(まるさ) + ramp(太さ)`、`score(choki) = ramp(とげ) + ramp(細長さ) + (1000 − ramp(太さ))`、`score(pa) = ramp(色の数) + ramp(色相) + ramp(大きさ)`。一番高いもの（同点は グー → チョキ → パー の順）。合成の特徴量 1 万件では 34 / 28 / 38 %。
v1 の色によるぞくせい（fire など 6 種）は**見た目だけ**に残す（技のエフェクトの色の候補）。

子ども向けの見せ方: 「グー（かたい）」「チョキ（するどい）」「パー（ひろがる）」。誰でも知っているじゃんけんで相性が分かり、パーは「かみ」なので紙に描く遊びとも合う。

## 4. レベルと成長

### 4.1 能力の伸び（普通のキャラ）

```
rg = Mulberry32(deriveSeed(seed, 11))
raw_i = 700 + a_i / 3 + rg.next() % 301
g_i = 最大剰余法(400, raw)                       // ‰／レベル、合計 400（平均 4 %）。なりやすい能力ほど伸びやすい
stat_i(L) = base_i + base_i · g_i · (L − 1) / 1000
```

### 4.2 経験値

- 次のレベルまで: `xpToNext(L) = 60 + 20·L + 3·L²/4`（Lv1→2 は 80、Lv10 は 335、Lv50 は 2935、Lv99 は 9390）。Lv100 までの合計は 351,165
- 一人用 1 戦: `基本（勝ち 100 / 負け 40）× (100 + 4·(ステージ − 1)) % × 再挑戦の係数 × 初クリア ×2 × 広告 ×2`
  - **再挑戦の係数**（経験値稼ぎの対策）: ステージが自分の Lv − 10 以上なら 100 %、−20 以上なら 50 %、それより下は 20 %
  - 広告の ×2 は 1 日 3 回まで（SPEC §12.1）。その 1 戦の結果に掛ける。一人用だけ
- 目安（自分の Lv のステージで勝率 70 %、ボーナス無し）: Lv5 まで約 5 戦、Lv10 まで約 20 戦、Lv20 まで約 60 戦、**Lv50 まで約 330 戦**、Lv100 まで約 1,200 戦。1 日 10 戦なら Lv10 は 2 日目、Lv50 は 1 か月前後、Lv100 は 4 か月前後（長く遊べる目標）。初クリアと広告のボーナスで 2–3 割ほど短くなる
- オンライン（サーバーで計算）: 勝ち 150 / 負け 60 × (100 + 4·(Lv − 1)) %。経験値がもらえるのは**1 日 20 戦まで**。**同じ相手とは 60 分に 1 回**まで、途中でやめた（切断した）負けは 0、ゴースト戦も同じ。広告の 2 倍は無し

### 4.3 ステータスポイント（パワーのたね）はやめる

理由: ①能力は「絵の見た目で決まる」というコンセプトがぶれる（硬そうな絵を AGI に振ると見た目と合わない）②サーバーで改ざんを調べるときの上限が緩くなる（v1 は「全部を 1 つに振った」場合を上限にしていた）③小さい子には振り方が難しく、上の子との差が開く。成長の楽しさは、進化の見た目・技が増えること・能力の数字が伸びることで出す。
（家族でのハンデ（docs/FAMILY.md）は「レベルを足す」方式のまま使える）

### 4.4 隠し要素: 大器晩成（内部名 `bloomer`）

**判定**: `s10 > 750`（skill > 75、v1 のしょぼキャラと同じ線）、または判定（origin）が `ai_generated`（クラウド）か `digital` / `printed` / `screen`（端末）。
見た目はシンプルなキャラにする（3D チーム: 形をふくらませるだけ、色を減らす、パーツを省く）。

| 時期 | 能力 | 技 |
|---|---|---|
| Lv1–49 | 予算 × **50 %**、成長率（‰）は普通のキャラと同じ → 増え方の絶対量は半分。**Lv49 でも普通のキャラの Lv12 くらい** | 予算 × **70 %**（普通のキャラは 95–105 %） |
| Lv50 で作り直す | 新しい「仮の Lv1」 = `(1400 + 3·75)·jitter/400` を、作り直し用の乱数（stream 13）で配分 → **普通のキャラ（kid 75、子どもの絵の平均くらい）の Lv50 と同じ強さ**になる。3D も本格的なモデルに作り直す | 4 つとも作り直す（stream 14）。予算は kid 75 の値 + でんせつ（Lv50）の +5 % |
| Lv50–100 | `stat = rb + rb · g · (100·49 + 112·(L − 50)) / 100000` → 成長は普通のキャラの **1.12 倍**。Lv100 で普通のキャラの約 1.05 倍 | — |

- **ばれないようにするため**: Lv50 では**全員**が大きく進化する（「でんせつ」。3D が豪華になり、技が +5 % パワーアップする）。隠し要素のキャラだけが作り直されていることは見た目からは分からない。成長の数字も「レベルアップで能力が上がった」としか見せない
- 経験値（隠し）: Lv49 までは**経験値 ×2、再挑戦の係数の対象外**。自分より弱いステージにしか勝てないので、これが無いと Lv50 に届かない。目安は Lv50 まで約 260 戦（普通のキャラは約 330 戦。負けが多いので、実際に遊ぶ時間は同じくらい）
- 結果（§10）: 同じ Lv（1–49）の子どもの絵には**全く勝てない（勝率 0 %）**。Lv50 で 48 %、Lv75 で 58 %、**Lv100 で 63 %**（一番よく描けた子どもの絵、kid 95 が相手だと 52 %）

|---|---|---|

| 25 | きらきら | 動くと光の粒が出る |

## 5. 技

### 5.1 種類（テンプレート 10 種）

| テンプレート | 種類 | 効果 | 主な数値の範囲 |
|---|---|---|---|
| strike / combo | 物理（1 回 / 2–3 回） | ATK（STR 系）と DEF で計算 | 威力 40–200、命中 60–100、会心 +0–20 |
| blast / barrage | 特殊（1 回 / 2–3 回） | ATK（INT 系）と RES で計算 | 同上 |
| heal | 回復 | 最大 HP × healPct × (75 + 50·INT/(INT+STR))%。**使うたびに 100 → 75 → 50 → 25 % に弱くなる** | 10–40 %、クールダウン 60 tick 以上 |
| power_up | 強化（自分） | 能力の段階 +1/+2（×1.25 / ×1.5） | 40–120 tick |
| weaken | 弱体（相手） | 段階 −1/−2（×0.8 / ×0.67） | 40–120 tick、命中 |
| poison | 状態異常「ねばねば」（どく） | 毎秒 最大 HP の 1.5 % を 8 秒 | 確率 30–100 % |
| paralyze | 状態異常「ビリビリ」（しびれ） | ゲージのたまり方 ×60 % を 6 秒 | 確率 30–100 % |
| barrier | まもり | 受けるダメージを 20–60 % 減らす | 20–60 tick |

ダメージ技には**追加効果**を 1 つ付けられる: ねばねば / ビリビリ（確率 10–50 %）、弱体 1 段階 6 秒、吸収（与えたダメージの 10–50 %）。
**眠り・行動不能・即死は入れない**（子どもが何もできない時間を作らない）。

### 5.2 ATK の式

| 式 | ATK | 防御 |
|---|---|---|
| STR80_AGI20（基本の物理） / STR70_VIT30（重い） / STR60_DEX40（器用） | 物理 | DEF |
| INT80_DEX20（基本の特殊） / INT70_RES30 / INT60_LUK40 | 特殊 | RES |

どの式も合計 100 % なので、予算は変わらない。端末のテンプレート生成では、キャラにとって ATK が一番高い式を選ぶ。

### 5.3 予算ポイント（AI が数値を決めないための仕組み）

「100 ポイント ≒ 同じ能力の相手に威力 100 のむぞくせい技 1 発 ≒ 最大 HP の約 10 %」を基準にする。

```
価値 value:
  ダメージ  = power × 命中/100 × (200 + 会心)/200 × 回数補正(1:100, 2:103, 3:106)/100 + 追加効果
            追加効果: ねばねば 確率×120/100、ビリビリ 確率×80/100、弱体 確率×40/100、吸収 drainPct×power/100
  回復      = healPct × 6
  強化      = 段階 × 時間tick × 5/8（AGI は ×1.2）
  弱体      = 強化と同じ × 命中/100
  状態異常  = (ねばねば 120 / ビリビリ 80) × 確率 × 命中 / 10000
  まもり    = 減らす% × 時間tick / 30
割引 discount = SP×5/4 + 溜めtick×2 + max(0, クールダウン − 無料分)/2   （無料分: 回復 60、強化/弱体 max(20, 時間)、まもり 40、その他 20）
               上限は value の 50 %（ただ同然の技を作れないように）
cost = value − discount ≤ スロット予算 × 技の倍率 / 100
```

| スロット | 解放 | 予算 | 決まり |
|---|---|---|---|
| 1「いつもの わざ」 | Lv1 | 100 | ダメージ技・**自分の属性**・SP 0・クールダウン 0・溜め 5 tick 以下（いつでも使える） |
| 2 | Lv1 | 100 | 属性は自分と**違う**もの（補助技はむぞくせい） |
| 3 | Lv10 | 120 | 自由 |
| 4「ひっさつ」 | Lv50 | 150 | ダメージ技・**むぞくせい**（v1 の「ひっさつは無属性」を引き継ぐ） |

技の倍率: `95 + kid/10`（95–105 %）。Lv50 で +5 %。隠し要素は Lv49 まで 70 %。

### 5.4 3 すくみ

技の属性 → 相手キャラの属性: 有利 ×1.5、不利 ×0.75、ほかは ×1（むぞくせいの技はいつも ×1）。**倍率はダメージに掛ける**（オーナーの値どおり。`typeStrengthPct` = 100 で、弱めるためのつまみも用意してある）。
有利な相手への勝率は 65–70 %（§10）。v1 のように「威力に基礎値を足して弱める」必要は無かった。理由: ①スロット 2 は自分と違う属性かむぞくせいなので、不利な相手にも逃げ道がある ②ひっさつがむぞくせい ③リアルタイムなので回復・まもり・状態異常の分だけ、相性の差がうすまる。

### 5.5 AI（Claude）が出力する JSON

スキーマ: `shared/battle_spec_v3/ai_moves.schema.json`（`moves` は 4 つ固定。インデックス 0–3 がスロット 1–4）。プロンプトで渡すもの: キャラの属性、スロットごとの予算、テンプレート表（範囲つき）、命名のきまり（ひらがな・カタカナ、10 文字以内、こわい・いやな言葉は使わない）、「数値は予算内で選んでね。超えたらゲームが縮めます」。

### 5.6 検証のきまり（`validateAiMove`、決定的。ゴールデンベクトルあり）

1. 知らない `template` → **その技を不採用**（そのスロットは端末のテンプレートで作った技に置き換える）
2. `name` がひらがな・カタカナ 1–10 文字でない、または NG ワード（`shared/ng_words` の正規化と同じ）→ 不採用。`flavor` が不正なら**空にするだけ**
3. `vfx` / `colour` / `atkFormula` が一覧に無い（または物理と特殊が合わない）→ 決まった値にする。`stat` が不正 → 不採用。追加効果の不正 → 外す
4. 数値: 整数でなければ切り捨て、範囲外は端に寄せる（警告に残す）
5. スロットのきまりを強制する: スロット 1 = 自分の属性・SP 0・クールダウン 0・溜め 5 以下、スロット 2 = 自分と違う属性（違反したら むぞくせい）、スロット 4 = むぞくせい、補助技 = むぞくせい、強化・弱体はクールダウン ≥ 効果時間
6. 予算を超えたら、主な数値を一段ずつ下げる（威力 −5 → 追加効果を外す／回復 −1 %／時間 −10 → 段階 −1／確率 −5／減らす% −5 → 時間 −5）。最小まで下げても超えるなら不採用
7. 予算より小さいのは許す（大きくはしない）
8. 結果（警告・不採用）はサーバーのログに残す。子どもには理由を見せない。AI の提案への通報（TRUST §6）はそのまま使える

### 5.7 端末のテンプレート生成（クラウドを使わないとき）

`generateOfflineMoves(genome, moveFactorPct, stream 12（作り直し後は 14）)`、画像ハッシュから決まる:
- スロット 1: 自分の属性のダメージ技。物理か特殊かは STR ≥ INT で決める。30 % は命中 90（その分強い）、20 % は弱体 20 % 付き。威力は予算いっぱい（5 刻み）
- スロット 2: 35 % は「自分の天敵に強い属性」（SP 10・クールダウン 30）、30 % はむぞくせい＋ねばねば／ビリビリ 30 %、35 % は補助（INT → 回復、DEF+VIT → まもり、LUK → 状態異常、STR+INT → 強化 の重みで選ぶ）
- スロット 3: 溜め技（SP 20・溜め 6・クールダウン 40）か連続技（SP 15・クールダウン 30）
- スロット 4: ひっさつ（むぞくせい、SP 40・溜め 12・クールダウン 80、威力 200）
- 名前: 属性ごとの擬音（ごつごつ／シャキーン／ふわふわ…）＋ 種類ごとの名詞（パンチ／ビーム／バリア…）。固定の語彙なので NG ワードは出ない

## 6. ATB リアルタイムバトル

### 6.1 時間と状態

- **10 Hz の固定 tick**（1 tick = 100 ms）。状態はすべて整数。ゲージ 0..10000、SP は 1/100 単位で 0..10000
- 1 tick の処理順（正規の順番）:
  1. タイマー（クールダウン、能力の段階、まもり、ビリビリ）を減らす。ねばねばは 10 tick ごとに最大 HP × 15‰（最低 1）。a, b の順
  2. SP が回復する
  3. ゲージがたまる（ためている側だけ）。10000 になったら `ready`
  4. 選択: ready の側は入力（コントローラー）を見る。無効な入力（クールダウン中・SP 不足・範囲外）は**無視する**。50 tick 選ばなければおまかせ（ready になった tick も 1 回目に数える）。技の SP を払い、溜め（cast）があれば casting に、無ければこの tick に解決する。casting の側は残りを 1 減らし、0 になったらこの tick に解決する
  5. 解決: a, b の順。**両方が同じ tick に解決するときだけ** `nextInt(2)` を 1 回引き、1 なら b から。HP 0 の側は行動しない
  6. 1800 tick（3 分）に達したら、HP の割合を整数で比べる（`hpA·maxB` と `hpB·maxA`）。完全に同じなら `nextInt(2)`
- 解決したらゲージを 0 に戻し、クールダウンを始める

### 6.2 ゲージ

```
rel(base, x, y, w) = base · (100(x+y) + w(x−y)) / (100(x+y))       // 相手との比。負の数にならない
fill = rel(280, AGI_me, AGI_foe, 30)           // 同じ AGI なら 280/tick → 36 tick（3.6 秒）で満タン
ビリビリのあいだは fill × 60 / 100
```
- AGI は**相手との比**なので、レベルが上がっても戦闘のテンポは変わらない。AGI が 2 倍だと約 1.2 倍の速さ
- **選んでいる間も相手のゲージは止まらない**。自分のゲージは満タンのまま止まる（SPEC §12.4）

### 6.3 選ぶ時間と「さきどり」（重要な発見）

シミュレーション: 選ぶのに 3 秒かかる側は、1 秒で選ぶ側に**20 %**しか勝てない。迷うと行動の回数が 3 割減るので、ルールどおり「迷うと自分が損」になる。ただし、子どもの手の速さで勝負が決まってしまう。
→ 対策（UI と 3D チームへの要件）: **ゲージがたまっている間に次の技をタップしておける（さきどり）**。満タンになった tick にすぐ出る（入力を待つ時間は 0 tick）。ゲージを止めないというルールは守ったまま、手の遅い子も損をしない（さきどりする側は、1 秒で選ぶおまかせに 68 % 勝つ）。

- おまかせ（一人用で常にオンにもできる）と CPU・ゴーストは、ready になってから **10 tick（1 秒）**考えてから選ぶ。おまかせが「一番強い操作」にならないようにするため
- 5 秒の時間切れ → おまかせが選ぶ（`autoPick` イベント）

### 6.4 SP

上限 100、開始時 40、回復は `rel(25, SP_me, SP_foe, 50)`（1/100 単位／tick。同じ SP の能力なら毎秒 2.5）。技の SP は 0–50。

### 6.5 ダメージ・命中・会心

```
ATK = (式 a の能力 × pa + 式 b の能力 × pb) / 100（段階込み）     DEF = 物理なら DEF、特殊なら RES（段階込み）
1 回あたりの威力 = power / hits
raw = 威力 × 2·ATK² / (ATK + DEF) / 100                         // 同じ能力なら 威力 × ATK / 100
dmg = raw × 60 × 相性% / 10000                                   // damageScalePct = 60
会心 ×150/100 → 乱数 ×(90 + nextInt(11))/100 → まもり ×(100 − %)/100 → ヒートアップ ×(100 + 3·秒)/100 → 最低 1
命中% = (命中×(DEX+EVA) + 15·(DEX − EVA)) / (DEX+EVA)、30..100 に収める。EVA = (AGI + LUK)/2
会心‰ = max(0, 50·(L_a+L_d) + 60·(L_a − L_d)) / (L_a+L_d) + 会心ボーナス×10
状態異常の確率 = rel(確率, LUK_自分, VIT_相手, 50)
```
乱数を引く順番（1 回ごと）: 命中 `nextInt(100)` → 会心 `nextInt(1000)` → 乱数幅 `nextInt(11)`（**外れても 3 つとも引く**）→ 全部終わってから追加効果を 1 回。段階: +n → ×(4+n)/4、−n → ×4/(4+n)、±2 まで。

### 6.6 おまかせ AI（`chooseMove`。CPU・ゴースト・時間切れで同じものを使う）

- 使える技（クールダウン 0・SP 足りる）を、**HP に換算した点数**で比べる（1 ポイント = 相手の最大 HP の 1/1000。§5.3 と同じものさし）
  - ダメージ技: 期待値（命中 × 0.95 × まもり）。倒せるなら最優先（SP・溜めが少ない技から）。追加効果は、相手がその状態になっていなければ価値を足す
  - 回復: HP 50 % 未満で回復量 ×1.2、75 % 未満で ×0.3、それ以上は 0
  - 強化: まだ強化されていなくて HP 40 % 以上なら価値 × 0.8。弱体: 相手がまだ弱っていなければ × 0.8。状態異常: 相手がまだかかっていなければ価値
  - まもり: 相手が溜めている（残り 2 tick 以上）か、相手のゲージが 85 % 以上なら価値 × 2、それ以外は × 0.3
  - 全部から引く: SP × 5/4 × 0.6 と 溜め tick（ポイント）
- 強さの段階: よわい = 40 %・ふつう = 10 %・つよい = 0 % の確率で、使える技からランダム（`nextInt(100)` → `nextInt(使える数)`）
- 乱数: AI 専用の stream（a = 1、b = 2）。バトルの乱数（stream 0）はずれない

### 6.7 オンライン（サーバーが正）

- サーバーが 10 Hz で同じ step を回す（Cloud Run / 専用サーバーなど、どこで回すかはインフラチームが決める）。クライアントは `{slot, clientSeq}` を送るだけ。**届いたら次の tick の手順 4 で使う**（さきどりならキューに入れておく）。無効な入力は無視する
- サーバーは「イベント（tick 付き）＋ 一定間隔の状態のハッシュ」を配信する。クライアントは 150–250 ms 遅らせて再生し、3D の動きでつなぐ（リアルタイムの格闘ではなく、選んでから出るまで時間がある遊びなので、遅延は見た目でごまかせる）
- 5 秒の制限時間はサーバーの tick で数える。通信が遅い子のために **+3 tick の猶予**をつける（`decisionTicks` + 猶予。spec 外のサーバーの設定）
- 切断: 10 秒戻らなければ、その側はおまかせで続ける（すぐ負けにはしない。戻ったらまた操作できる）。30 秒戻らなければ負け、経験値は 0
- 再現: `seed`、両方の入力ログ `(tick, side, slot)`、spec のバージョンがあれば試合全体を再現できる（通報の確認・不正の調査に使う）

## 7. 一人用（ストーリーなし）

- **10 ワールド × 10 ステージ = 100**。ワールド: らくがき のはら／クレヨン もり／えのぐ うみ／いろえんぴつ やま／ペンギン こおり／マーカー まち／ねんど さばく／はさみ おしろ／にじいろ そら／まっしろ ノート
- ステージ n のおすすめ Lv = n、CPU の Lv = n。CPU の能力をワールド内の位置で 88, 89, 90, 91, 92, 93, 94, 95, 96, **98 %（ボス）**にする（レベルの差は低い Lv ほど効きが強いので、レベルではなく割合で難しさを決める）
- CPU の AI: ステージ 1–20 よわい、21–60 ふつう、61–100 つよい。考える時間は 1 秒
- CPU のキャラ: 同梱の子どもの絵（今は 12 体）。**ワールドごとに 3–4 体、全部で約 30 体**欲しい（Vision の `gen_cpu_doodles` で作る。→ Q7）。ボスは大きく見せる（能力は表のとおり）

- ごほうび: 経験値（§4.2）と、ステージの星 1–3（勝つ／HP 50 % 以上残す／60 秒以内）。星を集めると**見た目のアイテム**（カードの枠・エフェクトの色・スタンプ）がもらえる。課金が無いので全部遊んで手に入る。能力には影響しない
- 小さい子向け: おまかせを常にオンにできる。負けたら「おすすめ Lv」と「もうすこし そだてて みよう」を出す（責めない）

## 8. オンラインのレート戦

- 解放は Lv5 から（v1 と同じ）。保護者の許可とサーバーの審査（SPEC §5）はそのまま
- **全員 Lv50 にそろえる**（`ratedStats(actualLevel)`）: 能力は**そのキャラ自身の成長のしかたで** Lv50 に計算し直す（低い Lv は上げ、高い Lv は下げる）。技は**実際に解放している分だけ**（Lv1–9 は 2 つ、10–49 は 3 つ、50 以上は 4 つ）。レベル上げの意味は「技が増える」として残る
  - 作り直し前の隠し要素は、**作り直し前の形のまま** Lv50 にする → とても弱い。レートが下がり、同じくらいの相手と当たる（隠し要素の意図どおり）。作り直し後は Lv50 で約 48 % なので、**レート戦は壊れない**。大器晩成の強さが出るのは、一人用・家族対戦・（将来の）マスターリーグ
  - 理由: レベルの差は大きすぎる（Lv+10 で 85 %）。レートが「どれだけ遊んだか」の指標になってしまい、始めたばかりの子が勝てなくなるため
- レート: **Elo**（サーバーで計算、プレイヤーごと）。開始 1000、下限 600。K は初めの 20 戦 48、その後 24、ゴースト戦は半分。期待値は 50 点刻みの表（33 点）を線形補間する（整数、§9）。Glicko-2 は数式が子ども向けの説明に合わず、Functions での実装も重いので見送り
- **バッジ（下がらない）**: たまご（開始）→ ひよこ 1050 → うさぎ 1150 → きつね 1250 → くま 1350 → ライオン 1450 → ドラゴン 1600 → でんせつ 1800。見せるのは**今までで一番よかったバッジ**。レートの数字は見せない
- マッチング: レートの差 ±100 から始め、5 秒ごとに +50、最大 ±400。**20 秒**で相手がいなければゴースト（v1 は 60 秒。子どもは待てない）。ゴーストはレートが近い登録キャラを選び、おまかせ AI（ふつう、1 秒）が動かす。ゴースト戦の K は半分
- 不正・談合の対策: 同じ相手との連戦は 60 分に 1 回まで（経験値もレートも）、1 日の経験値は 20 戦まで、切断の負けは記録する

## 9. エンジンに依存しない仕様（移植の決まり）

- **浮動小数点は使わない**。割り算はすべて**負でない整数の切り捨て**（どの式も、割られる数が負にならないように書いてある。`rel()`、命中、会心を参照）。途中の値は 2^53 未満（JS の Number でも正確）
- 乱数: Mulberry32（docs/BATTLE.md §2 と同じ、ビット単位）。stream: 0 バトル、1/2 AI（a/b）、10 能力の個性、11 成長、12 技、13 作り直しの能力、14 作り直しの技。`deriveSeed(seed, stream)` は v2 と同じ
- 画像の seed = 画像ハッシュ（16 進）の先頭 8 桁。16 進でなければ FNV-1a
- 入力の特徴量は**量子化した整数**（spec の `featureUnits`）。Vision は解析のときに 1 回だけ量子化して保存・送信する。サーバーは同じ整数から能力を計算し直して照合する（改ざん対策。v1 の `maxStatsAtLevel` はもう使わない）
- 正解例（`golden_vectors.json`、Dart の参照実装で生成）: deriveSeed 5、ゲノム 12（隠し要素 4 を含む、Lv 1/10/49/50/75/100 の能力、最大 HP、技の倍率）、端末の技生成 6、AI 出力の検証 10（受け入れ・範囲外を寄せる・スロットのきまり・予算に合わせて縮める・不採用）、技のコスト、**バトル 6 件**（Lv1–100、さきどり、時間切れのおまかせ、隠し要素）、経験値、Elo
  - バトルは入力（両方の能力・技・seed・考える tick）だけで再現でき、結果（勝者・tick・HP）と**イベント列の FNV-1a**（`"<tick> <type> k=v,..."` をキーの順に並べ、`\n` でつなぐ）で照合する。2 件はイベント列を全部入れてある（どこでずれたか調べるため）
  - `test/domain/battle_v2/spec_files_test.dart` が、JSON がコードと一致すること、JSON の入力だけでバトルを再現できることを確かめる
- 再生成: `cd app && dart run tool/v2_sim.dart spec` / `golden`

1 つの能力だけ +50 %（ほかは同じ、Lv20）: HP 91 / SP 70 / STR 83 / VIT 88 / DEF 80 / INT 76 / RES 76 / DEX 71 / AGI 92 / LUK 74 %。
**合計を変えずに AGI に寄せても 49 %（×1.5）、37 %（×2）**なので、AGI に全部振るのが得になることは無い（「強すぎない」）。AGI は 1 ポイントあたりの効きが一番大きい能力の 1 つなので、AGI が高いキャラは強く感じる（「効く」）。

レベル差（違う絵同士）: Lv6 vs Lv1 89 %、Lv15 vs Lv10 88 %、Lv55 vs Lv50 72 %、Lv60 vs Lv50 85 %、Lv100 vs Lv95 62 %（成長が Lv1 の値を基準にした足し算なので、低い Lv ほど差が大きい。v1 と同じ傾向）。

操作: つよい vs ふつう 52.8 %、ふつう vs よわい 55.0 %。さきどり（0 秒）vs おまかせ（1 秒）68.2 %、3 秒で選ぶ vs 1 秒 20.1 %（§6.3）。

### 10.2 調整の経緯（決めた理由）

1. 最初の値（ダメージ 100 %、ゲージ 3 秒、AGI の比 50 %、HP = 8·HP + 2·VIT）: 25–35 秒で終わって短すぎ、AGI +50 % が 92 %、kid 95 vs 60 が 90 %、隠し要素の Lv100 が 88 %
2. ダメージ 55–60 %、ゲージ 3.6 秒 → 平均 45–55 秒（目安 45–90 秒）。乱数の幅（70–100 %）や会心を増やしても勝率はほとんど変わらなかった（1 戦で 10 回ほど攻撃するので、平均に近づく）→ 90–100 % のままにした
3. HP +50 % だけで 97 % 勝つ → 最大 HP に「10 能力の平均 × 5」を入れ、HP の能力は ×3 に下げた
4. 子どもの絵らしさ: 予算の傾きを 2 倍 → 1.5 倍（`1400 + 3·kid` を 400 で割る）、jitter を ±5 % → ±3 %、技の倍率を `90 + kid/5` → `95 + kid/10` にした（kid 95 vs 60: 90 % → 75 %）
5. 隠し要素: 作り直しを kid 85 相当にすると、Lv50 で 63 %（レート戦で強すぎる）→ **kid 75 相当（Lv50 で互角）**にして、Lv50 からの成長 ×1.30 → ×1.12（Lv100 で 88 % → 63 %）。Lv49 までは、予算 40 %・成長 50 % だと Lv49 でも普通のキャラの Lv1 より弱く、遊べなかった → 50 % / 100 %（Lv49 で普通のキャラの Lv12 くらい）
6. 相性: ひっさつに属性があると、Lv50 で相性有利が 79 % → ひっさつを**むぞくせい**にして 70 %
7. ステージ: レベルで差をつけると、Lv+2 のボスが 31–40 %、−3 が 95 % になった（低い Lv ほど差が大きい）→ 能力の割合（88–98 %）にした

### 10.4 わかっていること・限界

- 合成した特徴量はランダムな一様分布なので、実際の子どもの絵の分布ではない。**実際の絵（Amateur Drawings の手元サンプル・社内のテスト）で、属性の割合と kid の分布を確かめること**（Q1）
- 戦闘の勝ち負けは急に決まる（能力が 20 % 違うと約 88 %）。1 戦で 10 回ほど行動するので、乱数で逆転しにくい。子ども向けに逆転の仕組み（HP が少ないとゲージが速くなる、など）を入れるかどうかは Q5
- AI の強さの差が小さい（つよい vs ふつう 54 %）。今の難しさの調整は CPU の能力の割合がほとんど担っている。つよい AI を「相手の溜めを見てまもる」「相性で技を選ぶ」方向に強くする作業が残っている
- 「3D で動き回る」演出の時間は計算に入れていない。技の溜め（cast）が演出の時間になるよう、3D チームとすり合わせが要る（Q6）

## 12. 未決定事項（オーナー・PM に確認したいこと）

1. **実際の絵での調整**: なりやすさの ramp の範囲、属性の割合（目標は各 1/3 ± 10 %）、kid の分布を、実際の子どもの絵 300 枚以上で確かめる（Vision と一緒に）
2. **最大 Lv100 と Lv50 までの時間**（1 日 10 戦で約 1 か月）。隠し要素の作り直しに届くまでの時間として長すぎないか
3. **写真の扱い**: SPEC §12.2 は「写真のような絵」を隠し要素にするとしているが、端末では人物の写真を見分けられないので、写真は今までどおり拒否にした。クラウド判定が許可されていて「人物が写っていない」と判定されたときだけ隠し要素にする案もある

6. **3D の演出時間**: 技の溜め（0–2 秒）とクールダウンを演出の長さに合わせるか、演出の間も時間を止めずに進めるか（今の案: 止めない。溜めがそのまま「ためる動き」の時間）

8. **パワーのたねをやめる**こと（§4.3）。v1 のキャラは振ったたねを捨てて作り直す（v1 は公開前なので移行は要らない、という前提）
